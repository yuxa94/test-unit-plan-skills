# 치수

## 사용자가 정할 것 (`profile.dimensions`)

| 항목 | 질문 예 | 관찰(참고만) |
|---|---|---|
| 치수 체인 | 어떤 체인을 어느 면에? (MC 전체 / MC 분할 / 안목 / 외부 / 개구부) | P4: MC + 안목 + 외부(창), P6: 외부(50) + 안목 2종 |
| 치수 스타일 | MC용·안목용 스타일 이름 또는 템플릿 | `MCDIM-50`, `MCDIM_40`, `HAUD-100`, `HAUD-안목치수`, `HAUD-외부(50)`, `DIM-50`, `SCALE` |
| 간격 | 외곽에서 첫 치수선까지, 체인 간 간격(축척 반영) | — |
| 문자 재정의 | 계산값과 다른 표기 허용? | 기본: 재정의 금지 |

스타일 이름의 숫자를 축척으로 믿지 않는다. 템플릿에서 실제 DIMSCALE·문자높이·화살표를 읽는다(`unit-plan-standards`).

## 절차

1. **기준점 계산** (model.json에서):
   - MC: walls `axis`의 좌표(외곽 → 바깥 체인), 세대 전체 = 양 끝 축선.
   - 안목: finish 루프의 마주 보는 두 면. ㄱ자·오픈 실은 루프 전체 폭이 아니라 실명 위치를 지나는 선이 처음 만나는 양쪽 면 사이를 잰다(전체 폭을 재면 거실 6370처럼 틀린 값이 나옴).
   - 원본 비교 시 주의: 원본 MC 치수가 `MC` 레이어 선 기준인지 벽 중심선(`CEN_*`) 기준인지 먼저 확인한다. 청주 원본은 창·벽 단위로 쪼갠 상세 체인(`NDIM40-in`)이었다.
   - 외부: 벽 몸체 바깥 면.
   - 개구부: openings의 rough opening 양 끝.
2. 면(북/남/동/서)마다 체인을 바깥에서 안쪽 순으로 쌓는다(외부 → MC 전체 → MC 분할 → 개구부). 실내 안목 치수는 실 안에 배치하되 실명·가구와 겹치지 않게.
3. `vla-adddimrotated`(직교) 또는 `vla-adddimaligned`로 작성하고 `stylename`을 지정한다. 문자 재정의(TextOverride)는 쓰지 않는다.
4. 각 치수에 `refs`(어느 벽/개구부의 어느 점인지)를 model.json `dimensions`에 남긴다 — 벽이 바뀌면 다시 계산.
5. 작도(`dim-001`…): `dim` 레이어.

## 구현 상태

- `run_reference_unit.mc_chains`: 남측·동측 외곽에 닿는 벽 중심선으로 MC 전체·분할 체인을 만든다. 스타일은 config `layers.dim_mc`다.
- `chord`: `clear_dim_rooms` 실의 실명 위치를 지나는 가로·세로 안목 치수를 만든다(ㄱ자 실 대응). 스타일은 `layers.dim_clear`다.
- 개구부·외부 상세 체인과 북·서측 체인은 미구현이다.

## 확인

- DBX 재읽기로 모든 치수의 `Measurement` = 계산 거리(±0.5mm), TextOverride 비어 있음.
- MC 분할 합 = MC 전체, 안목 + 벽두께 합 = MC 분할(차이는 표로 보고).
- 체인끼리·문자끼리 겹침 없음(문자 위치 bbox 검사).
- `review.json.dimensions`: 체인 수, 불일치 목록.
